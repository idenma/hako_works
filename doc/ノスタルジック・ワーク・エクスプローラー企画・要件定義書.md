# ノスタルジック・ワーク・エクスプローラー企画・要件定義書/2026年11月1日版

## 1. プロジェクト概要

- **プロジェクト名（仮）:** ノスタルジック・ワーク・エクスプローラー
- **開発環境:** Rust、Bevy 0.20
- **ターゲット層:** 幼児、および同等の認知能力を持つ方
- **コアコンセプト:** 失敗のない安全な世界で、自分の行動が世界を変え、誰かの役に立つ喜びを直感的に味わえる箱庭ゲーム。
- **最終的な舞台:** 懐かしい日本の田舎を思わせる、東西南北がつながった2km四方の街。

この文書では、将来目指すゲームの仕様と、現在動作しているプロトタイプの状態を分けて記載する。実装の進捗は日々の作業記録にも記録するが、仕様との違いを判断するときは本書の「目指す仕様」と「現在のプロトタイプ」を参照する。

## 2. ビジュアルと世界観

- **アートスタイル:** PS1時代のローポリゴンを基調に、形や色を整理した、見分けやすいデフォルメ表現。
- **舞台:** 日本の少し田舎めいた街。最終的な広さは2km四方。
- **主人公:** 小学3年生くらいの少年。
- **ランドマーク:** 火の見櫓、御神木、煙突など、遠くからでも区別できる特徴的な目印を街の各所に置く。
- **道と障害物:** 通れる道と、川・生垣など通れない場所の違いを見た目で分かりやすくする。

## 3. UI/UXと操作方針

### 目指す仕様

- 基本操作は移動と、ひとつのアクション操作を中心にする。操作に迷わないよう、必要な操作を画面上で短く案内する。
- 必要な道具がない、または所持していても選択されていない場合は、次に必要な道具や操作を短い言葉で案内する。
- 文字をなくすのではなく、幼児にも伝わる短い言葉を使う。難しい言葉や長い説明を避け、漢字は小学2年生までに習うものを目安にする。
- 会話は吹き出しの短い言葉と、キャラクターの動き・表情、3Dオブジェクト、効果音、カメラ演出を組み合わせて伝える。
- アイコンや接近表示は言葉を置き換えるものではなく、操作できる対象を見つけるための補助として使う。
- 次にすることを文章だけで説明せず、困っている人物、必要な物、使う道具を近くに配置し、視線や動きで気づけるようにする。
- ゲームオーバー、時間制限、HP、落下ダメージなどの罰を設けない。試した行動に対して、安心できる反応を返す。

### 現在のプロトタイプの操作

現時点では、操作確認のためキーボード・ゲームパッド向けの入力を実装している。目指す操作体系とは異なる部分があるため、今後の調整対象とする。

- 移動: WASD、上下矢印キー、またはゲームパッド左スティック
- カメラ旋回: キーボードの左右矢印
- ジャンプ: Spaceキー、またはゲームパッドのEastボタン（XboxのB／PlayStationの○）
- 対象へのアクション: `E`、またはゲームパッドのSouthボタン
- 道具選択: `1`またはゲームパッドの十字キー左で斧、`2`または十字キー右で木材
- メモ帳の開閉: `N`、またはゲームパッドのStartボタン。開いている間は移動、カメラ旋回、ジャンプ、道具選択、アクションを停止する。

## 4. 遊びと進行

- **探索の反応:** 歩く、物に近づく、物を拾うなどの行動に、視覚・聴覚で分かる反応を返す。虫や水しぶき、どんぐり、スタンプラリーなどは今後追加する候補。
- **近くで完結する課題:** 問題と解決手段を近い場所に置き、長距離のお使いを基本にしない。
- **橋づくりの基本体験:** 川を渡れない人物や橋の材料となる木を手掛かりに、斧で木を切り、得た木材で橋を作る。橋ができたことと、人物の反応で仕事の成果が伝わるようにする。
- **メモ帳:** 川辺の人物に近づくと「はしを つくる」が記録される。斧は木を切るための道具、木材は完成時に消費する材料として表示する。木材がそろうと川辺へ戻るよう案内し、建設地点ではメモを閉じて道具を選ぶ・作業するよう案内する。完成後は「かんりょう」と表示する。
- **働く喜びの発展案:** クレーンの操作や、トラックによる自動運搬などを通じ、作業の過程と成果を見せる。仕事の完了時は街の変化や周囲の人の反応で達成感を伝える。

## 5. ワールドとアーキテクチャ

### ワールド規模とチャンク

- 開発初期は、1チャンクを10m×10mとする20×20チャンク（200m四方）を対象にする。
- 最終目標は同じ大きさのチャンクによる200×200チャンク（2km四方）。
- 東西南北の端がつながるワールドを目指す。現在の試作では、プレイヤー座標をワールド端で折り返す方式を使う。
- プレイヤー周辺のチャンクだけをEntityとして生成し、範囲外は破棄する。チャンク定義と進行状態は、読み込み中のEntityとは分けて保持する。
- 地形の種類、配置物、配置位置、回転、衝突形状をデータとして扱う。見た目のモデルとゲーム内の判定は独立して差し替えられるようにする。
- 川などの地形は、描画寸法と通行判定に共通の設定値を使い、見た目と判定のずれを防ぐ。
- チャンクごとの配置数には上限を設ける。現在は定数とテストで確認しており、実行時の入力検証・エラー通知は今後整備する。

### Bevy ECSの設計

- **Entity / Component / System:** プレイヤー、配置物、チャンク、UIなどの状態をComponentとして表し、処理はSystemに分ける。
- **ワールド状態:** 橋の完成など、チャンクの読み込み・破棄を越えて残す状態はResourceに保存する。配置物ごとの取得・伐採状態もワールド上のEntityとは別に保持する。
- **変更通知:** 状態変更を他のEntityへ直接伝播させず、必要に応じてBevy 0.20のMessageで通知し、それに応じるSystemが見た目やNPCの状態を更新する。
- **クエスト:** 固定の`QuestId`とアイテムIDで必要な道具・材料を参照する。開始済みIDはResourceに保持し、材料の所持数とワールドの完成フラグから現在の案内を決める。材料が複数ある場合は全種類の個数を確認してから消費する。
- **責務の分割:** アプリの起動、プレイヤー、インタラクション、インベントリ、クエストとメモ帳、セーブ、シーン、ワールド定義を機能ごとのRustモジュールに分ける。
- **アセット:** ゲームで使用するモデルやフォントは`assets/`以下に置く。地形やUIなど、ゲーム内の制御と密接な形状はプリミティブで生成してよい。
- **日本語表示:** Bevyの`complex_script_segmentation`を有効にし、日本語の文字区切りを処理する。表示内容が変わらないHUDは毎フレーム更新しない。

## 6. 現在のプロトタイプ（2026-11-11時点）

### 実装済みの主な機能

- Bevy 0.20で動作する3Dプロトタイプ。
- 20×20チャンクのワールド定義と、プレイヤー周辺3×3チャンクの生成・破棄。
- ワールド端での座標折り返し、川の通行制限、橋完成後の通行。
- プレイヤーの移動、カメラ旋回、ジャンプと重力。試作の丘では歩行時に地面の高さへ追従し、空中では地形に着地する。
- 3×4チャンクにまたがる、滑らかに接続した小さな丘の地形メッシュ。
- 斧の取得、斧を使った木の伐採、木材を使った橋づくり。
- 川辺のNPCとの接近をきっかけに始まる橋づくりクエストと、必要なもの・戻り先・完了状態を確認できる開閉式のメモ帳。
- 橋の完成状態や取得・伐採状態をResourceに保持し、チャンク再読み込み後の再生成に反映。
- 近くの実行可能な対象を優先して選び、画面上の短い操作案内と対象近くのポップアップを表示。必要な道具がない場合も、斧の入手、道具の選択、木材の入手など次の手順を案内。
- 川辺のNPCとの会話を画面下部のHUDに表示。NPCから水平距離6m以内で表示し、離れると隠す。橋完成後の台詞切り替えにも対応し、会話の3D板は撤去。
- 起動時にプレイヤー、カメラ、HUD、NPC、会話表示の必須Entity数を確認し、欠落・重複をエラーログに記録。GLB・フォントなどのアセット読み込み失敗も、パスと原因をエラーログに記録。
- プリミティブによる地面・川・橋の建設地点・UI表示と、GLBによるプレイヤー・NPC・木・斧・橋のモデル表示。橋の完成後は一体型の`bridge.glb`を表示する。
- HUD用の日本語フォント。

### 現在のアセット

- `assets/3D_Object/`: `player.glb`、`riverside_npc.glb`、`tree_oak.glb`、`axe_pickup.glb`、`bridge.glb`
- `assets/fonts/mgenplus-1p-regular.ttf`: HUDと会話表示用フォント

### 現在の確認状況と未対応

- 2026-11-01、ユーザーによる起動・通常プレイの確認で問題がなかった。
- 2026-11-09、ユーザーが`cargo run --release`でプレイ確認を行い、斧の取得、木の伐採、橋づくり、チャンク範囲外への移動と再訪後の状態保持がすべて問題なく動作することを確認した。
- 2026-11-09、ユーザーによるジャンプと重力の動作確認で問題がなかった。
- 2026-11-10、ユーザーがセーブデータの起動時読込と終了時保存を確認した。丘の追加後に、以前丘の範囲にあった木のIDがワールド定義から抜け、保存済みの伐採状態を読み込めない問題が見つかった。丘の地形定義後も既存の木IDを保つよう修正した。丘の描画・移動・ジャンプ着地は実装済みで、画面上の確認はこれから行う。
- 2026-11-11、一体型の橋モデルを川を横断する向きと長さに合わせ、ユーザーが橋を作れることを確認した。建設前の丸太はNPCと重ならない位置にプリミティブで表示する。実際に橋を渡る操作の確認はこれから行う。
- メモ帳とクエストの表示・操作、旧セーブの引継ぎは自動テストと分離したセーブデータで確認済み。ユーザーによるプレイ確認はこれから行う。
- NPCの歩行・指差し・橋を渡るアニメーション、カメラによる視線誘導は未実装。NPCは静止し、橋完成後は台詞が切り替わる。
- 進行状態、インベントリ、開始済みクエストは、終了時にユーザーデータ領域の`hako_work/progress.ron`へ自動保存し、次回起動時に自動読込する。保存形式バージョン1も読込可能で、完成済みの橋は完了済みクエストとして引き継ぐ。形式バージョン、アイテムID、配置オブジェクトID、クエストIDを検証する。プレイヤー位置やジャンプ中の状態は保存しない。
- 衝突判定は簡易段階で、川と橋の通行判定を中心に扱う。木など全配置物との汎用的な衝突は未実装。
- 地形は試作の丘1か所のみ。段差・複雑な斜面、丘の配置データ化、歩行中の環境反応、トラック運搬、クレーン操作は未実装。
- アセットの読み込み失敗はログに記録する。画面上の通知や代替表示は未実装。
- 配置数上限を含むインメモリ配置定義の起動時検証を実装済み。外部データの読込検証や、この一連のプレイを自動化した統合テストは今後の課題。

### 拡張基盤の実装度（2026-11-04）

実装度は、現在合意しているプロトタイプ範囲の完了度を示す。将来機能まで含めた完成度ではない。

| 項目 | 実装度 | 現在の範囲・残作業 |
|---|---:|---|
| アイテムの安定ID | 100% | `ItemId`を導入し、斧と木材に固定IDを割り当てた。IDから種類への変換も確認する。 |
| クエストの安定ID | 試作 | `QuestId`と必要品の定義を導入。現在は橋づくり1件で、NPC接近による開始と完成フラグによる完了に対応する。 |
| 配置オブジェクトID | 100% | `ObjectInstanceId`を配置物の識別子として使い、ワールド全体での重複を検証する。既存IDは再利用・別用途への変更をしない。 |
| インメモリ配置データの検証 | 100% | ワールド起動時にチャンク範囲・欠落・配置数・重複ID・位置・回転・Collider寸法を検査する。エラーがあれば起動を止める。 |

## 7. フェーズと次の進め方

### フェーズ1: 移動と基本案内（基礎実装済み）

プレイヤー移動、NPCの短い吹き出し、接近時の操作案内・ポップアップを実装済み。基本シーンを起動して通常プレイできることを確認した。

### フェーズ2: ワールド状態と近距離の課題（基本体験を実装済み）

Resourceによる進行状態、変更通知、斧・木材・橋の一連の操作を実装済み。2026-11-09に、チャンク範囲外へ移動して戻った後も状態が保たれることを含め、ユーザーによるプレイ確認を完了した。斧の取得から橋づくり、チャンク離脱・再訪までを実際のBevyシステムで通す自動テストも追加した。今後は案内・エラー表示などの完成度を高める。

### 次に優先する作業

2026-11-09、ユーザーによるワールド端・モデルの表示確認と、ジャンプの動作確認が完了した。橋づくりからチャンク再訪までの自動テストも追加済み。2026-11-10、セーブ／ロードの動作確認が完了した。

1. メモ帳の開閉と操作停止、必要品・戻り先・完了表示、再起動後の状態を実際に確認する。既存セーブを消さずに確認する場合は別の`XDG_DATA_HOME`を使う。
2. 丘の見た目、坂の上り下り、ジャンプ後の着地、チャンク境界での接続をプレイ確認する。
3. クエストの種類や発生条件を増やし、必要に応じて外部データ化や汎用的な設置状態の保存を検討する。
4. 木などの配置物を含む衝突判定や地形定義を整え、NPCの演技、カメラ誘導、歩行中の環境反応を追加する。
5. 上記を踏まえてから、クレーンや自動運転トラックなどの仕事体験へ進む。

## 8. 初期モックアップ要件の扱い

開発開始時には「1つの`main.rs`に、Bevy標準プリミティブだけを使った実行確認用モックアップを作る」ことを想定していた。
この制約は初期検証用のものであり、現在のプロジェクト構成を制限しない。
現在はRustモジュールに分割し、GLBモデルと日本語フォントを導入している。
以後の実装は、本書の「目指す仕様」と「現在のプロトタイプ」を基準に行う。
